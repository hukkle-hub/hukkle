# 흥양기 API — 배포방법

Supabase Edge Function `hy` / 프로젝트 `ybflkszmymalhafzzdbs`

## 절대 규칙

1. **`verify_jwt = false`** — 이 함수는 JWT가 아니라 `x-player` 헤더로 인증한다. 켜면 전부 401이다.
2. **`deno.json`을 반드시 files에 포함**하고 `import_map_path`를 `deno.json`(상대경로)로 명시한다.
   빼먹으면 이전 배포의 절대경로가 캐시돼 "import map path does not exist"가 난다.
3. **압축 번들을 부트스트랩에 싣지 않는다.** 2026-09-01에 그 형태의 base64 블롭이 손상돼
   서버가 통째로 죽었고 원본 복구가 불가능했다. 소스 그대로 올린다. (design_decision #50)

## 대시보드에서 배포 (탭에서도 됨)

1. `supabase.com/dashboard` → 프로젝트 `ybflkszmymalhafzzdbs`
2. Edge Functions → `hy` → Deploy / Edit
3. 이 폴더의 6개 파일을 그대로 올린다
   `index.ts` `engine.ts` `rules.ts` `routes2.ts` `sinpyo.ts` `deno.json`
4. **Verify JWT 끄기**
5. Deploy

엔트리포인트는 `index.ts`. 로컬 import는 `./engine.ts` `./rules.ts` `./routes2.ts` `./sinpyo.ts`.
외부 의존성은 `jsr:@supabase/supabase-js@2` 하나뿐이다.

## CLI

```
supabase functions deploy hy --no-verify-jwt --project-ref ybflkszmymalhafzzdbs
```

## 라이브 검증하는 법

로그 도구와 web_fetch가 막혀 있으면 DB에 임시 `http` 확장을 깔고 서버측에서 함수를 직접 때린다.

```sql
create extension if not exists http with schema public;
create or replace function public._hy(m text, p text, b text default null)
returns text language plpgsql as $$
declare r public.http_response;
begin
  if m = 'GET' then
    select * into r from public.http((
      'GET','https://ybflkszmymalhafzzdbs.supabase.co/functions/v1/hy'||p,
      ARRAY[public.http_header('x-player','<player_id>')],NULL,NULL)::public.http_request);
  else
    select * into r from public.http((
      'POST','https://ybflkszmymalhafzzdbs.supabase.co/functions/v1/hy'||p,
      ARRAY[public.http_header('x-player','<player_id>')],'application/json',b)::public.http_request);
  end if;
  return r.status || ' ' || left(r.content, 900);
end $$;
```

**엔드포인트는 반드시 한 문장에 하나씩 호출한다.** 한 문장에 여러 개를 엮으면 타임아웃 시
트랜잭션은 롤백되는데 HTTP 부수효과는 이미 커밋돼 되돌릴 수 없다. (카드가 두 번 제물로 날아간 적 있다)

끝나면 `drop function public._hy(text,text,text); drop extension http;`
